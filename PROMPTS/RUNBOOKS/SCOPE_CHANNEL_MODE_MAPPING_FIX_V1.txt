MISSION_ID: SCOPE_CHANNEL_MODE_MAPPING_FIX_V1

TITLE
Fix inverted Scope Channel Mode mapping (Stereo selection shows M-S and vice versa)

SYMPTOM
In the Stereo Scope view:
- Selecting “Stereo” displays Mid-Side behavior
- Selecting “Mid-Side” displays Stereo behavior

ROOT CAUSE (most likely)
One of these is inverted:
1) APVTS AudioParameterChoice order vs UI ComboBox order
2) ComboBox item IDs vs parameter index mapping (JUCE: combo IDs are 1-based, choice index is 0-based)
3) The scope DSP/router interprets the enum backwards (switch/case swapped)

GOAL
Make scopeChannelMode consistent end-to-end:
- UI label “Stereo” => scope runs Stereo (L/R)
- UI label “Mid-Side” => scope runs M/S (Mid = L+R, Side = L-R)
No other behavior change.

HARD RULES
- Minimal diffs
- Do NOT rename parameters
- Prefer not to change the underlying AudioParameterChoice index order (avoid breaking saved sessions)
- No allocations in audio thread

FILES ALLOWED (tight scope)
- Source/ui/scope/* (the scope component that applies channel mode)
- Source/ui/layout/ControlRail.cpp (only if combo mapping is wrong)
- Source/PluginProcessor.cpp (ONLY if AudioParameterChoice definition is wrong; last resort)
