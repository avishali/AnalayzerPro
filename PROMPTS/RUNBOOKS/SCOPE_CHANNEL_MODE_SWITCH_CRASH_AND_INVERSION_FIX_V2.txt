MISSION_ID: SCOPE_CHANNEL_MODE_SWITCH_CRASH_AND_INVERSION_FIX_V2

TITLE
Fix VST3 crash when switching scope mode + fix true Stereo<->MidSide mapping (not just default UI)

SYMPTOMS
1) VST3 crashes when changing scope mode from Stereo to Mid-Side.
2) Mapping still feels inverted (Stereo shows M/S behavior and vice versa).

ROOT CAUSES (MOST COMMON)
A) Mapping bug:
   - ComboBox IDs (1-based) written directly into AudioParameterChoice (0-based), producing wrong value.
   - Choice order differs between UI and AudioParameterChoice.
   - DSP router switch-case swapped.
B) Crash bug:
   - Out-of-range channel access on switch (host may deliver 1 channel in some cases).
   - Invalid parameter value (e.g., 2 when only {0,1}) causing invalid enum/switch path.
   - Scope FIFO/renderer reading buffers with mismatched sizes during mode transition (no guard).

GOAL
- Selecting “Stereo” ALWAYS uses L/R.
- Selecting “Mid-Side” ALWAYS uses Mid=(L+R)/2 and Side=(L-R)/2.
- Switching modes NEVER crashes in VST3.
- Parameter order preserved (no session recall break).

HARD RULES
- Minimal diffs.
- Do NOT change AudioParameterChoice order unless you implement migration (avoid).
- Clamp parameter values defensively at the point-of-use.
- No allocations on audio thread.
- Keep scope visual behavior otherwise unchanged.

FILES ALLOWED
- Source/ui/layout/ControlRail.cpp (only if mapping/attachment is wrong)
- Source/ui/scope/* (where scope mode is applied/rendered)  <-- search by "scopeChannelMode"
- Source/PluginProcessor.cpp (ONLY to inspect param definition; do not reorder choices unless unavoidable)

- then cast to enum / switch

This alone often stops the VST3 crash if param receives 2 or -1 transiently.
